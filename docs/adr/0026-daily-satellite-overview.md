# 0026 — 全国态势每日遥感增量与历史快照

日期：2026-09-16。状态：已实现，待部署验证。

全国态势需要每日更新干旱和洪涝，并能查看当天和历史。逐地块独立下载会重复读取相邻地块共用影像；只刷新查询缓存则无法保证新影像已入库，也无法稳定保留历史。

采用现有Celery Beat、Internal HTTP、`satellite_batch`任务、OSS/MQ结果写入和`overview_stats_daily`，不新增调度服务或数据库表。

```mermaid
flowchart LR
    B[Beat 北京时间19:15] --> H[Internal HTTP]
    H --> A[API 全量有效地块与已有观测日期]
    A --> G[空间索引 + 5×5 km分组]
    G --> Q[MQ或HTTP claim任务]
    Q --> W[共享S1/S2窗口下载与地块裁剪]
    W --> O[OSS场景结果 + 结果MQ]
    O --> P[API机结果入库]
    H --> C[API检查任务与入库明细]
    P --> C
    C --> D[同一次分类生成全国/省/市/县每日快照]
    D --> U[每日态势 / 历史趋势 / 日期查询]
```

- 所有周期任务默认关闭，由env逐项开启。开启`SCHEDULE_DAILY_SATELLITE_ENABLED=true`后，每天北京时间19:15检查全部未删除地块的S1和S2；共享Celery配置显式使用UTC，调度为11:15 UTC。天气、旧每周逐地块光学、旧每日总览缓存分别有独立开关，均默认false；每日聚合链路通常不需要同时开启旧调度。
- 复用锚点中心的米制5×5 km矩形，完整边界包含才能合组，超大地块独立保留完整范围。空间索引先筛邻居，降低全国分组的远距离比较开销。下载机按该5×5 km矩形检索和读取共享窗口，逐地块使用完整边界掩膜并发布结果；跨出窗口的地块不参与该组。
- 这是每日发现全量地块、增量下载新观测。所有地块只检索包含统计日在内的近7个自然日，按S1/S2分别复用数据库已有日期跳过策略，禁止每日重复下载已入库日期。多年历史仍使用既有三年批量回填接口。
- 每天用确定性UUID和API事务锁只建立一个全国批次。所有组和日期分片先落Job，派发确认存入批次；HTTP失败重试继续原统计日并补派未确认任务。MQ本身是至少一次投递，发布与派发确认之间崩溃仍可能重复投递；沿用任务完成检查与结果幂等写入。
- 下载完成不能代表结果入库。worker记录成功发布的地块/日期，API一次性核对传感器、地块和日期的结果存在性。Celery每5分钟延时重试，不占用worker等待。没有新景也生成每日快照；超过23小时的未完成任务、入库缺失、失败任务或无效边界将批次和快照标为partial。旧worker缺少发布明细时不允许直接认定入库成功。
- 干旱沿用现有光学质量门槛、干旱季节和景均值分类。洪涝接入项目已有`classify_flood_series`，使用统计窗口内S1轨道历史基线及VV下降/VH辅助判断；修复原总览只调用单景watch分类、无法产出确认洪涝的问题。一次读取全国地块和所需S1/S2景均值，按同一分类结果汇总全国到县；避免各级重复读取像元导致内存压力和口径不一致。删除的地块不参与统计。
- 快照采用截至统计日近60天内最新可用影像，记录有效分类对应的采集日期、当日观测、历史沿用、未知地块数。这里的沿用只发生在有效窗口内，云量不合格、超窗和不适用干旱季的数据为未知；缺测不等于正常。S1、S2并不保证每个地块每天都有可用观测。[Copernicus S1](https://sentiwiki.copernicus.eu/web/s1-mission)、[Copernicus S2](https://sentiwiki.copernicus.eu/web/s2-mission)。
- 快照保存当时区划和面积，各级结果一起提交。保存后禁止总览upsert覆写snapshot=true的行；同日期批次完成后重复调用直接返回。历史只读已保存快照，缺失日期不补零、不调用实时计算冒充当时结果。

页面默认读取最近已保存结果并显示其统计日期。当天仍在下载时展示阶段；如果显示前一天则明确说明当天快照尚未生成。历史模式支持日期查询和近30天趋势；区间分析保留任意日期和作物物候选择，用于查看已有影像和尚未建立每日快照的历史。每日快照使用统一默认物候口径；区间分析的作物选择仅影响弱长势。

代价：首轮全国7个自然日观测仍可能耗时较长；每日下载窗口缩短后，窗口外历史影像不再由该任务补拉，仍需通过既有批量回填接口处理。固定60天有效窗口仍是快照分析口径，窗口内沿用较旧观测会降低态势时效性，因此必须展示覆盖信息。去云结果通过既有异步链路产生，入库检查确认原始产品落库；快照仅采用生成时已入库且通过质量门槛的产品，晚到去云结果进入后续统计日，不改写历史。灾情判定复用现有算法，历史样本不足的低VV景仍只标为积水关注，不冒充已确认洪涝。
