# ADR 0031：统一虚拟项目区遥感拉取链路

## 状态

已接受

## 背景

此前定时日增量、周度光学补拉、Smart同步、单地块回填、批量回填和报告触发分别创建遥感任务。部分入口使用旧5×5 km聚合，部分入口直接按地块下载；只有虚拟项目区历史任务会将整区像素保存到OSS，造成同一区域重复检索、下载及处理。

## 决策

- 将API侧`build_vpa10_satellite_jobs`作为新增遥感任务的统一规划/构造入口：先按完整包含关系复用已有项目区，没有归属时运行10×10 km动态窗口规划器，再创建区域共享`satellite_batch` Job。
- Job明确携带`virtual_area=true`、`virtual_area_tile_id`和持久化项目区边界；下载机优先读取OSS压缩像素JSON缓存，未命中时整区下载并回存缓存。
- 共享资产不替代地块结果。下载机继续按地块原边界裁剪S2指数、S1 VV/VH等像素及统计，再经原结果管线写入`parcel_scene_products`和地块JSON。
- 日增量、周度过期补拉、Smart完整同步、Smart显式同步后的遥感回填、前端单地块/批量回填、评估/生育期报告、管理员历史回填和新建地块历史初始化统一创建虚拟项目区任务。
- 周度地块有不同的缺测起点时，同一区域使用最早缺测日期作为共享下载范围；各地块仍按数据库已有日期跳过重复产品。
- 迁移期保留旧`satellite_analysis`消费者处理已入队消息；新增业务入口不再生产逐地块遥感任务。天气、土壤等非像素遥感数据仍使用各自链路。

## 取舍与风险

- 区域任务可以下载完整窗口，但Job中的`land_ids`只包含当前触发方要求处理的成员；OSS缓存覆盖完整项目区，避免非请求地块意外产生或覆盖结果。
- 项目区窗口可能比单块地需要的空间更大，但跨入口复用资产可减少重复STAC请求和下载，并保证像素网格一致。
- OSS缓存读取或写入失败不阻断地块结果发布；下载任务继续走STAC并记录缓存异常，后续任务可以补建资产。
- 不新增数据库表或迁移脚本；依赖现有虚拟项目区、地块关系、OSS资产索引和`satellite_batch`结果写入路径。
