# 项目监测一期

项目页保留地图为主的布局，增加六项统计、风险分色、筛选联动、地块详情及数据有效性提示。无需数据库迁移；前后端需一同部署。

## 数据入口与范围

- 新增 `GET /v1/projects/{group_id}/monitoring?freshness_days=14`，使用种植项目 `group_id`，不是历史 `farm_id`。
- API 机器批量读取项目内未删除的地块、最近两个不同日期的有效 S2 产品、未关闭预警及有效期内的已关闭预警。只返回指标摘要与边界，不传输像元。下载机没有新增数据库访问。
- 业务系统的完整地块名单决定页面范围，遥感数据按 `land_id` 补齐。未同步到遥感库的业务地块仍显示；遥感库中已移出当前业务名单的地块不计入。
- 业务地块接口取消固定 50 页截断，分页无进展时报错。项目监测摘要没有 500 条截断。列表每次渲染 100 条并提供加载更多，统计与地图始终使用完整筛选集合。
- 业务名单加载失败时不展示部分统计；监测接口失败时业务信息仍可看，预警、覆盖率显示未知而非零。

## 风险与数据有效性

风险等级使用既有预警，不新增农情阈值或灾害诊断。严重红色、中度橙色、轻度黄色；有有效观测且无当前预警记录用绿色；缺数据或观测过期且无风险依据用灰色虚线。选中地块增加外描边，不替换风险色。

未关闭预警始终保留，观测过期时同时展示过期状态。已关闭光学预警若仍在有效期内、尚无该指标的更新有效观测，保留风险依据，但不计入待处理数。关闭不代表恢复；新观测也仅表示旧依据被替代，页面“暂无异常”指当前没有预警记录，不是作物健康认证。沿用已有预警规则，生育期规则的进一步完善不属于本期。

有效监测定义为指定天数内、通过现有 `official_s2_sql` 质量规则且 NDVI 有效的 S2 产品。默认 14 天，页面可选 7、14、30 天；这是观测新鲜度策略，不是预警阈值。最近两个不同日期用于计算 NDVI/EVI/NDMI 的绝对差值；同一天的原始与去云产品不作为两期。

## 六项统计

统计卡片、列表和地图使用同一筛选集合，并注明“当前数量 / 项目全部数量”。

| 指标 | 口径 |
| --- | --- |
| 地块数量 | 按地块 ID 去重，附未标绘数量 |
| 地块总面积 | 优先业务地块面积；缺失时使用遥感主表亩数，再用公顷乘 15；项目登记面积不混入 |
| 有效监测覆盖率 | 有效观测地块面积 / 当前全部地块面积；附有效地块数 |
| 预警地块数 | 按地块去重并取最高风险等级，附严重/中度/轻度数量 |
| 预警地块总面积 | 预警地块去重面积及占比，不表示实际受灾面积 |
| 待处理预警 | 完整未关闭预警记录数，独立于预警地块数量和详情前五条预览 |

缺失面积不视为零：合计注明仅统计已知面积，覆盖率和面积占比在缺少分母时显示未知。零地块时不展示虚假的 100% 覆盖率。

## 交互与验证

支持名称/编号/作物/负责人搜索，风险、作物、种植状态、数据状态、未标绘/待处理筛选；严重风险优先排列。详情显示基础信息、风险依据日期、数据来源与有效期、最近指标差值及完整详情入口。桌面为侧栏，手机为接近全屏面板，Escape 关闭并恢复焦点。

后端测试：`python -m unittest discover -s tests -p test_project_monitoring.py -v`。运行 API 全套测试需把 `packages/agric_satellite_analysis_common` 放入 Python 模块路径，限流测试可使用进程内 `settings.redis_url = 'memory://'`，不改部署配置。

前端验证：`node scripts/verify-project-monitoring.mjs`、类型检查、Lint、三语言检查、生产静态构建。`scripts/verify-project-monitoring-ui.py` 使用本地静态页面与独立的模拟接口验证桌面/移动端、筛选联动、详情、空结果、缺边界及加载失败；不会读写真实业务数据。
