# ADR 0031：Sentinel-1 场景级 Sigma0 定标

- 状态：已采纳
- 日期：2026-09-28

## 背景

旧流程把 Sentinel-1 GRD 幅度 DN 除以固定 1000 后转 dB。VV/VH 的洪涝阈值直接使用绝对 dB，固定比例不能代表每景产品的真实校准系数；以公开 Planetary Computer 场景的同一窗口比较，新旧算法中位数相差约 4.05 dB。

ESA Level-1 产品为每个极化提供 `sigmaNought` 查找表。该表随方位行和距离列变化，必须在原始影像像素坐标做双线性插值；定标后在线性功率域重投影，再换算为 dB。实现遵循 Sentinel-1 Level-1 校准向量定义与插值要求，见[ESA 校准技术说明](https://sentinels.copernicus.eu/documents/247904/685163/S1-Radiometric-Calibration-V1.0.pdf)和[Sentinel-1 处理说明](https://sentiwiki.copernicus.eu/web/s1-processing)。

## 决策

1. 同景 VV/VH 都有 calibration XML 时，按各自 `sigmaNought` LUT 计算 Sigma0；只提供一个极化 LUT 时整景失败，避免一个极化准确、另一个近似的混合输出。
2. 从目标网格边界反算并裁剪原始 COG 像素窗口，按源像元中心和校准 LUT 逐像元计算 `DN²/Aσ²`；随后在线性功率域重采样，最后转 dB。GCP影像的控制点平移到裁剪窗口局部原点后参与warp。
3. 非标准 STAC 目录同时缺少两个 LUT 时保留 `/1000` 兼容回退，但产品元数据标明 `fixed_amplitude_scale_approximation` 与比例值。只有确认使用场景 Sigma0 LUT 的数据绘制基于绝对阈值的雷达水体候选色斑；旧版或近似值仍可查看时序分类，但界面需标明定标口径不确定。
4. 产品 JSON、COG provenance 与 API 记录定标方法。批次窗口缓存把校准资产纳入指纹并升级 schema；去云窗口数组换到新版本目录。
5. 洪涝历史基线按“相对轨道 + 定标方法/回退比例”分组。旧记录、近似回退和新 Sigma0 LUT 数据不会互相作为 VV 中位基线；轨道样本不足时只回退到相同定标组。
6. 不在此改动里声称处理了噪声或完整地形校正。`thermal_noise_correction` 只记录本项目代码路径没有应用噪声 LUT；上游资产可能存在独立处理，需结合具体 STAC 产品说明和农业地块样例核实。

## 兼容和迁移

历史数据库行不强制迁移，缺少定标记录的场景继续参与独立的旧口径统计基线，并在详情显示口径未知；其绝对阈值像元色斑隐藏。用户或调度任务重算场景后，upsert 会用新算法版本和定标元数据替换原场景。历史/新产品过渡期由分组基线隔离，避免它们互相提供VV下降基线。

本次修正的 `stac-s1-lonlat-v4` 与 `uncrtaints-decloud-v3` 历史产物也不会自动重算。部署后应按日期和地块分批强制回算并检查覆盖率/失败率；回算完成前历史产品仍代表旧的“先插值幅度”路径。

## 验证

- 公开场景 `S1A_IW_GRDH_1SDV_20240325T055038_20240325T055103_053134_066FC4` 的 15×13 地块窗口：LUT 结果中位数 −10.44 dB，旧固定比例 −14.49 dB，差 +4.05 dB。该差异只代表这个场景与窗口，不是跨景固定偏移。
- 用合成栅格核对 NoData、固定比例回退、LUT 双线性插值、LUT 行范围裁剪和缓存指纹变化。
- 阈值含义、噪声处理和输入资产上游处理仍需在农业区真实样例上与参考产品/地面记录核对；不能仅凭单个公开窗口认定洪涝精度。

### 实现收尾复核（2026-09-28）

- 依据ESA校准说明复核公式和处理顺序后，发现上一版先通过 `WarpedVRT` 对幅度做双线性重采样，再应用Aσ LUT；这会先平均DN再平方，不符合逐源像元校准后再平均功率的定义。
- 现在按目标投影网格边界反算源COG窗口，直接读取原始像元，在原始行列中心应用LUT并计算线性功率，再一次warp到目标网格；不带LUT的兼容回退也直接从源窗口warp，去掉中间VRT和重复重采样。
- 定标按128行块计算，避免整窗float64中间数组扩大峰值内存；目前尚无大地块时延/内存基准。
- S1产品算法标识升为 `stac-s1-lonlat-v5` / `s1-4.0.0`，批次窗口缓存升为v5，去云产品算法标识升为 `uncrtaints-decloud-v4`，防止旧重采样数组继续冒充新算法产物。
- 静态检查后，从生产源码抽取窗口/定标函数，在内存构造的仿射等价GCP栅格上验证裁剪+GCP平移warp与整幅源warp的400个目标像元一致（最大绝对误差0）；合成DN=4、Aσ=2也得到Sigma0功率4。该烟测不覆盖真实S1 GCP布局、NoData/景幅边缘和产品参考值。
- 随后以无操作占位模块绕过仅供未调用COG写出路径使用的`rio-cogeo`导入，直接调用生产`_read_band_windowed_db_profiled`读取Rasterio内存GCP GeoTIFF；窗口裁切、GCP平移、源像元定标、NoData处理及目标warp与整景参考的400个有效像元一致（最大dB绝对误差0）。这只验证读取链路的合成输入行为。
- 通过Planetary Computer对真实公开场景`S1A_IW_GRDH_1SDV_20240325T055038_20240325T055103_053134_066FC4`做VV小窗口读取，使用真实Sigma0 LUT。生产裁窗为299×402源像元；另读取向四周扩展128像元的555×658参考窗口并独立warp到同一64×64目标格，4096个有效像元掩膜完全一致，最大dB绝对误差0。该抽样覆盖真实COG/GCP/LUT的读取组合，但参考使用同一解析后LUT，不验证校准值相对官方处理软件的科学准确性；单次`io_ms=8333`也不是吞吐基准。输出结果后本地Python进程未在30秒工具等待内正常退出，最终手动终止；需区分栅格结果已产生与退出清理异常，并进一步检查导入/关闭生命周期。
- 当前环境仍缺少`rio-cogeo`，仓库也无本地真实S1 COG；尚未导入完整worker或核对VH通道、景幅边界、真实NoData与权威参考产品。公开VV抽样不能代替完整科学验收。
